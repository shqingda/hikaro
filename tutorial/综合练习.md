### 主作业：把命令回执接到真实 SQLite

[`labs/08-reliability.mjs`](labs/08-reliability.mjs) 里的 `Receipts` 是内存版。把它换成 `node:sqlite` 实现，保持这些行为：

| 场景 | 期望 | 怎么证明 |
| --- | --- | --- |
| 同 id 同内容，两个连接同时提交 | 只有一个拿到执行资格 | 两个**独立数据库连接**的结果 |
| 同 id 不同内容 | 明确冲突，无第二次修改 | 错误信息 + 副作用次数 |
| 同 id、不同设备 | 不共享回执 | 按认证得来的 scope 隔离 |
| 写回执前进程被杀 | 重启后报告 `unknown`，不自动重跑 | 数据库记录 + 实际文件内容 |
| 宿主重启后查旧的 `accepted` | 报告 `unknown` | `hostInstanceId` 比较 |

要求：

- 回执查询和插入在同一个 `BEGIN IMMEDIATE` 事务里（参考第 6 章和 Hikaro `acceptCommand`）。
- 文件副作用和数据库**不在同一个事务里**，这个窗口要用 `unknown` 诚实表达。
- 每个测试先确认“删掉保护代码会变红”。
- 别用同一个连接里两次同步调用冒充并发。

交付物：实现、测试、一页决策记录（模板见下）、一段“还没测什么”的说明。

### 项目介绍四句话

1. **解决什么问题**：一个本地 Coding Agent，根据用户目标请求模型、调用工具、保存执行记录。
2. **关键边界**：原生模式由 Hikaro 自己驱动循环，pi-ai 只是模型适配库；`--backend pi` 是另一条执行路径。
3. **一个你真正掌握的难点**：比如取消与迟到结果、文件修改冲突、回执丢失后的未知状态。
4. **证据与限制**：在什么环境、用什么测试观察到了什么；没做过的（真实终端交互、生产模型评估）明确说没做。

### 六组常见追问

**A. 模型返回工具请求，为什么不能直接执行？**
它是外部输入。要经过：工具查找 → 运行时校验（类型只在编译期）→ 路径/权限 → 执行状态（没取消、租约还在）。追问：校验过了但路径指向外部？审批等太久租约丢了？`data` 会进模型上下文吗？（第 1、4、5 章）

**B. JavaScript 单线程，为什么还有竞态？**
每个 `await` 都是一个缝隙，条件可能在缝隙里变了。例子：检查暂停 → await 准备 → 用户已暂停。generation 解决“旧响应覆盖新视图”，文件锁解决“两个写入者”，别混用。（第 3、8 章）

**C. 点了取消，为什么还显示“停止中”？**
提出取消和确认收尾是两件事。控制命令绕过队列，但工具要自己响应信号；进程组要 SIGTERM → 等 → SIGKILL → 确认。（第 3、5、8 章）

**D. 已经加密了，为什么还要防重放和审批？**
完整性、连接新鲜度、业务幂等、操作授权是四个问题：认证加密、挑战值 + seq、命令回执、审批与撤销复查。（第 8 章）

**E. 模型说改好了，你怎么验收？**
看实际修改和独立检查，不看最后一句话。`completed` 只是循环结束。成本缺失记 `null` 不记 0。（第 8 章）

**F. 一个绿色的测试，你为什么怀疑它？**
目标函数真的被调用了吗？错误原因对吗？参数是不是先抛错了？有正向对照和副作用断言吗？删掉保护代码它会变红吗？（第 8 章）

### 让 AI 帮你复查，而不是替你写

> 先不要改代码。给出一个可能让它失败的输入，说明会错在哪一步。

确认反例后，再决定要不要采纳它的修改。
