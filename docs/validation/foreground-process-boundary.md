# 前台进程边界验收 · 2026-10-24

## 交付

前台 Shell 复用后台的原组停止器和 macOS 身份探针。取消/超时会核实原组终止；失败保留未知退出码并报告仍可能存活。主进程退出与输出管道关闭分开处理，继承管道的脱离后代不再使调用永久等待。输出及日志可能缺失时明确提示，脱离后代不作为信号目标。详见 [规范与限制](../specs/foreground-process-boundary.md)。

大结果在取消后仍记录工具终态、消息和有界清理数据；当前租约检查保持不变。未添加恢复旧 PID 的控制入口，也不声称阻止存活旧进程的后续文件副作用。

## 精简

- `9008232`：后台与前台共用 `ProcessGroup`、`ProcessObservation`，不再维护两套信号升级逻辑。
- `931e62f`：前台边界及取消证据修复。Shell 显式启用观察，搜索、索引、Git 读取继续使用低成本路径。
- `1fbe134` 独立整理提交将输出捕获、截断、归档和 flush 收在局部 `captureProcessOutput`；生命周期函数保留三个含义不同的等待条件，不新增通用框架。终端复用既有环境变量白名单。
- 相关测试按独立故障核对：保留前台/PTY 组内取消、普通/模型调用、权限与租约差异。新自然退出/取消共享一个脱离进程 fixture，权限失败/无法确认终止共享另一个 fixture。没有为了数量指标删除独立覆盖，也没有增加映射内部实现的断言。

## 验证

- 先确认自然退出和取消继承管道的用例均在 8 秒期限失败，再修至通过。真实后代保持存活，未收到针对其 PID/PGID 的终止信号。
- 原有“主进程先退出、组内后代忽略 SIGTERM”保留，并增加原组清理 confirmed 断言。
- EPERM 与 SIGKILL 后仍存活均有界返回失败、exitCode 为 null；EPERM 返回后再运行新命令并等待 1.2 秒，无旧调用迟到信号。
- 大结果覆盖手动/模型调用取消后的 tool.end、transcript、artifact 及清理摘要；真实租约过期拒绝 artifact；对象数据按 UTF-8 8 KiB 限界，非普通对象不展开。
- 手动原生检查：60,012 字节 Unicode 输出完整归档、0600 权限、目录失败报告，以及真实 timeout 原组确认终止，全部通过。
- 反转 `outputIncomplete` 判断的 mutation 被真实自然退出回归拦截；恢复源文件后再运行最终检查。
- 独立审阅覆盖信号归属、迟到回调、终态、输出生命周期和租约边界；没有阻塞项。

- 最终 `pnpm check`：126 个应用测试文件、652 项测试、15 项脚本检查通过；类型、构建、未使用绑定和残留引用检查通过。
