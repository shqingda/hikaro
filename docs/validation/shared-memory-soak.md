# 共享合计内存与长时测量（2026-10-21）

历史阶段：按旧 RSS 门槛判断失败。最终新口径验收结果见本文末尾；旧数据与判断保留用于追溯。

## 实现与定向验证

- 三处 Zod 命名导入改为 namespace 导入，避免当前 esbuild/Zod 组合保留所有未使用 locale。最小构建从约 454 KB 降至 85 KB；生产构建测试确认只保留实际默认的英文错误消息，不删除验证规则。
- 相同状态文字不再触发 TUI 重绘。回归测试在旧实现准确记录 100 次无变化更新导致的 100 次重绘，修复后无新增重绘，状态改变仍更新画面。
- 连接层通过 `needsSynchronization` 读取布尔状态，不为内部同步判断深拷贝历史、流式文本等 UI 快照。附着视图的同一同步回调复用一次快照，异步请求前后仍分别核验连接与会话；外部 `state` 仍返回隔离副本。
- 打包与 planning 定向测试 5 项通过；TUI interactions 19 项通过；client-core/connection 19 项通过；attached-workflows 3 项通过。根项目及移动端类型检查通过。候选在独立输出目录完成构建，避免覆盖正在测量的基线构建。
- 规划文本拆分、SQLite 语句缓存和 benchmark 脚本是前轮尚未提交的候选，本轮测量包含它们，不能将它们单独视为已通过内存验收。

## 启动验收

候选构建 3 次预热、30 次附着启动、每次 20 个 PTY 输入样本：启动 p95 175.81 ms（门槛 200 ms），输入 p95 0.86 ms（门槛 16 ms）；客户端 RSS p95 58.63 MiB，host RSS p95 70.89 MiB，同一采样时刻的合计 RSS p95 **129.36 MiB**（门槛 100 MiB，失败）。合计由逐次相加后取 p95 得出，不是两个独立 p95 相加。测量时另有隔离的 soak 进程运行；所有样本保留。

## 长时验收

测量使用本机 Node 26.12.0、macOS arm64、独立临时 home、实际 shared host + attached TUI、真实 SQLite worker 和本地 SSE fixture。每 20 秒输入唯一任务，核对屏幕输出、持久化 run.end=completed；预热 1 分钟后连续记录至少 30 分钟。每个进程的 ps RSS 相加，禁止改用 process.memoryUsage 或物理 footprint 替代门槛。验收进程未启用 inspector、堆采样、强制 GC 或重启。未使用 --check 提前退出，以保留完整失败窗口；结果仍按同样的 100 MiB / 10% 上限计算。

原基线最终完成 30.0016 分钟、94 条任务，host/TUI 均以 0 退出；RSS 合计 162.86 →185.00 MiB（+13.59%），原始报告保留旧口径 failed。候选报告最终记录 38.87 分钟、84 条任务、两进程退出码 0；与预期 20 秒节奏不符，需排查采样间断，不能仅凭 elapsedMs 宣称连续窗口合格。两个旧报告均没有 footprint/PSS，不能用来判定新内存口径通过。

## 独立诊断（不作为验收）

相同 40 秒加速工作负载的 allocation sampling：TUI 样本总分配量从约 113.73 MiB 降至 87.70 MiB，state 副本分配从 31.91 MiB 降至 8.89 MiB。采样只用于定位，不能等同于 RSS 降幅或长期无泄漏。

另一轮独立的 60 秒堆区诊断中，TUI heapUsed 约 12.48 → 12.24 MiB，heapTotal 15.19 → 20.44 MiB；new_space 容量增加约 3 MiB，code_space 容量增加约 1 MiB。RSS 增长至少部分来自 V8 堆区与编译代码扩容，不能全部归因于被保留的业务对象，也不能据短测排除其他泄漏。

未采用诊断用的 V8 参数作为生产修复，未降低性能阈值，也未更换 RSS 口径。剩余工作需要同时解决双进程常驻基线与持续运行的堆容量增长；只减少临时分配无法保证 100 MiB 合计达标。


## 本轮最终构建验收（完成）

前轮产品优化的 48 项定向检查、根项目与移动端类型检查、构建通过。补充存储检查 14 项通过、1 项失败：lease-fencing 的 prompt → 手动工具连续调用，prompt completion 早于 drain 的空队列清理结束，executeTool 因 busy 拒绝。相同用例在 HEAD 7abedc5 的隔离源代码副本（不含候选优化）复现，属于已有问题；不能宣称所有存储测试通过。临时副本 pnpm 自动依赖校验曾报 symlink hoist 目录错误，随后 Vitest 实际执行并复现相同业务失败。

冻结本轮 pnpm build 产物，以 caffeinate -i 防止空闲休眠，运行 bench-soak --check；不禁用墙钟/单调时钟 40 秒间断检测，不强制 GC，不重启进程。完整结果：[原始报告](footprint-30m.json)。连续测量 30.00218 分钟，含预热共完成 94 条任务；91 个测量样本，最大墙钟采样间隔 20.06 秒，host/TUI 退出码均为 0，fixture 无错误，--check 退出码 0。运行结束重新核对所有记录的构建文件 SHA-256，全部一致。

macOS 系统归属 footprint（host + 一个 TUI，SQLite worker 含在 host）：起点 83.1039 MiB，终点 92.7547 MiB，峰值 98.5664 MiB。首 5 分钟中位数 87.5266 MiB；15–20 分钟 92.1887 MiB，20–25 分钟 95.7214 MiB，最后约 5 分钟 92.2775 MiB。未强制 GC；上升后自然回落，末窗口接近 15–20 分钟窗口。该工作负载未发生 OOM、崩溃或任务超时；未采集全系统压力，因此不宣称排除了内存压力。

判定：本次 30 分钟功能稳定性通过，候选优化的定向回归及类型/构建检查通过，可以提交。内存评估建立首个完整 footprint 基线，未发现本窗口持续不回落的单调增长，但不能排除更长时间泄漏；没有匹配的旧构建 footprint 对照，不声称本轮减少了多少物理内存。memoryPassed 仍为 null，平台绝对预算、Linux 实机、多客户端、真实模型与更长周期仍待评估。已有 prompt completion / drain 收尾竞态单独待修，不将其隐藏或标为通过。

发布估算：TUI 89%，移动端 35%，未到 95%。本轮增量是完整连续功能窗口与可追溯内存基线，不是取消旧门槛带来的进度。
