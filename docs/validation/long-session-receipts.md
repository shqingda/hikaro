# 持续会话回执终态回收（2026-10-21）

## 修复

持续会话中的 prompt 在执行结束前就返回 accepted。客户端的即时 command.receipt 查询也可能只得到 accepted，此后不再查询，导致已完成任务一直占用 60 个写入回执槽。真实 host + PTY 诊断在完成 61 条任务后拒绝下一条输入，报 `Command receipt capacity exceeded; synchronization slots reserved`。

ClientConnection 在下一条普通写入之前查询旧回执，只有 host 确认 completed/failed 才允许既有有界队列回收。未知结果继续保留，查询不会重放写入。取消、审批、握手及快照不等待该步骤；异步查询跨越连接 epoch 后拒绝发送原写入。旧 host 不支持回执查询时保持兼容行为。

## 验证

- 新回归测试连续执行 100 个任务，模拟即时 accepted 查询之后才完成/失败，确认每条任务只发送一次且回执数不超过 64。将实现临时替换为 HEAD 原版本，测试准确复现容量错误；已恢复修复版本。
- `pnpm test tests/client-connection.test.ts tests/client-core.test.ts`：19 项通过。
- `pnpm typecheck`、`pnpm build`：通过。
- 真实本地 SSE fixture + host + PTY 加速诊断完成 123 条任务，跨过旧容量阻塞点，随后触发现有 128 次会话模型调用预算（包含摘要调用）。另一轮受预算约束的诊断在 60 秒内完成 81 条并正常退出。

以上是定向功能验证，不是 30 分钟稳定性验收。诊断构建还包含工作区中未提交的内存候选改动，不能作为独立提交的发布性能证据。

## 尚未通过

共享合计 RSS 100 MiB 门槛与预热后 30 分钟增长不超过 10% 仍未通过。堆快照诊断会触发 GC 并显著扰动 RSS，不纳入验收：同一诊断约 15 秒至 55 秒，host 主线程保留大小从 23,695,696 增至 24,098,848 字节，存储 worker 从 7,397,033 增至 7,420,217，TUI 从 13,459,375 增至 14,089,231；增长主要为代码相关节点，不能据此排除其他泄漏或宣称 RSS 达标。

原 10 秒一次、30 分钟的 fixture 会超过产品调用预算；待验收脚本调整为每 20 秒一条，为摘要保留调用数，不修改产品预算、测量窗口或内存阈值。SQLite 语句缓存、规划模块拆分与该脚本仍为工作区候选，未随本次回执修复提交。
