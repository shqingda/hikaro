# 当前 TUI 启动与输入复测 · 2026-10-23

两组使用同一构建集合，SHA-256 `a9304d815b8cdff011dd4298d8be271c5d35270e968d0568f1000b453b8af585`。完整文件摘要、原始样本、首轮及主机负载均保存在 [普通模式数据](performance-20261023/standalone.json) 和 [附着模式数据](performance-20261023/attached.json)。

每组先保留一次首轮，再预热 3 次、测量 30 次，每次输入 20 次，使用原有 nearest-rank p95 算法。两组顺序执行，没有同时运行构建或测试；已有模拟器和 Metro 保留。操作系统缓存是热的，子进程使用每次新建的隔离 V8 缓存和测试数据目录。没有为了过门槛改样本数、丢弃样本或切换为共享热缓存。

命令为 `pnpm bench:check` 与 `pnpm bench:attach:check`，仅通过 `HIKARO_BENCH_OUTPUT` 改变报告保存路径。两命令退出码均为 0。本次未改性能实现，不把与历史数据的小幅差异解释成优化收益。

范围只覆盖 PTY 启动至可用帧，以及 PTY 输入至编辑器回显；不等同物理屏幕或中文 IME 延迟。附着模式计时从已就绪 host 的客户端启动开始，不包含 host 冷启动。没有请求真实模型、测量流式事件至终端增量、10k 历史渲染或 30 分钟稳定性；RSS 仅作诊断，沿用 [内存口径](../specs/shared-memory-soak.md)，不拿 RSS 合计否决或代替 footprint/PSS 验收。
