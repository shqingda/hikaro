# 执行历史分页验收 · 2026-10-23

普通和附着 TUI 的 `/tasks history` 现在查看全部已保留、具有有效运行 ID 的运行记录；`/tasks history RUN_ID` 可直接读取旧详情。直接阅读不暂停队列。管理器 `/tasks` 的历史分类复用相同浏览器，保留管理器原有的暂停语义。后台终端、子任务的独立持久索引与全文搜索仍未交付。

## 已验证行为

- 每页最多处理 200 条源事件，加一条后页探测，最多返回 20 次运行。固定快照配对开始/结束，按最后实际处理位置推进；重复事件造成的空页仍可继续。刷新才纳入更新的事件。
- 超过原窗口的 225 次运行按顺序完整遍历，无重复或丢项；开始记录在扫描窗口之外仍能配对。分页期间追加结束记录不改变旧快照，精确查询可读取当前状态。缺少结束记录继续显示未知。
- 真实 host 验证只读角色可读、其他会话和撤权后拒绝、无持有令牌要求；普通请求等待时两个历史方法仍从有界控制通道完成。旧 `execution.read` 数组与最近 100 次运行兼容。
- 旧 host 或只支持一个新方法时，直接入口明确要求升级；原管理器仍显示“最近历史”及 200 条事件/100 次运行范围。
- 共享面板验证上一页快照、空页、刷新、导航值与运行 ID 不冲突、详情不暴露动作；坏游标被拒绝。关闭、切换会话或断连后，迟到请求和正文不能更新新面板。

## 实际 TUI 与故障回归

普通、附着各一条真实 PTY 流程：225 次持久运行，浏览 12 页至最早记录，打开详情，退出并重启后按 ID 直接读取；附着同时重启 host。浏览前后 450 条运行事件逐字相同。观察探针先通过普通管理器验证生效，再确认历史阅读没有调用 `holdQueue` 或 prompt；没有用空探针文件冒充有效检查。

审查发现列表带回 20 份完整详情时，4000 个控制字符组成的字段经 JSON 转义可使响应达到 1,495,070 字节，超过 RPC 上限。先复现，再将统一运行时列表改为摘要。真实 RPC 回归覆盖 20 个长 ID 与控制字符字段，列表低于 32 KiB，单条详情低于 128 KiB；随后 `session.current` 和再次翻页仍成功，host 保持可用。

新存储模块加入分发复制清单；独立临时目录中的复制 worker 能启动并读取历史列表、详情与原有答案草稿。旧库首次建索引、两连接并发打开、建索引失败事务回滚及修复后重试均有回归。

普通 TUI 切会话竞态由独立审查在真实 PTY 复现：已在途的 `/resume` 完成后，旧历史详情或列表仍可能显示。新增三个回归先全部失败，再以切换期间入口保护和原面板失效信号修复；直接详情、管理器列表与切换中的新读取均通过。动态导入完成前已失效的 reader 静默退出，不打开面板、不暂停队列，也不抛出迟到错误。相关日志 `/tmp/hikaro-history-selection-{red,green,regression}.log`。

## 旧库升级观察

[原始报告](performance-20261023/execution-history-migration.json)记录 100,000 条总事件、20,000 条运行事件、10,000 次运行，升级前数据库 37,486,592 字节。两连接首次打开并读取首屏共 98.64 ms；后续页 1.98 ms，最旧详情 0.72 ms。查询计划分别使用范围索引与运行 ID 索引，没有全表扫描或临时排序。

这是有并发仓库测试负载的一次合成观察，证明该规模升级与查询正确，不是静默性能基线或性能门槛验收。首次建索引仍需要扫描旧事件。复现脚本保留为 [execution-history-migration.mjs](performance-20261023/execution-history-migration.mjs)，从仓库执行 `node --import tsx docs/validation/performance-20261023/execution-history-migration.mjs`；脚本使用隔离临时数据库，并覆盖同目录观察报告。
