# 待发消息恢复验收 · 2026-10-20

## 实现

SQLite 保存待发正文、图片、顺序及来源身份。host 在持久写入后确认接受；派发前原子领取并删除记录，已领取消息不自动重放。`/tasks` 将重新加载的消息标为待确认恢复，支持编辑、删除、明确确认恢复发送；仅待确认消息存在时，会话不显示为运行中。恢复检查原来源身份，并沿用当前会话权限及工具审批。

正常退出保留已恢复但尚未确认的记录；显式取消仍清除待发记录。会话删除清理持久队列。旧 RPC 未知回执仍供核对，不因恢复动作改写为成功。

唯一 PTY 脚本启动独立 demo host，通过认证 RPC 暂停队列并提交消息，核对持久接受后 SIGKILL host；重启并加载恢复记录，再正常退出及重启，核对消息仍存在。附着 TUI 使用原身份打开详情、逐级 Esc 返回、关闭管理器，核对没有用户消息写入；重新打开并明确确认后，核对恰有一条用户消息与 demo 回复，持久队列为空。

存储/核心测试覆盖正文编辑、图片数量保留、队列排序、错误身份拒绝、删除、一次性领取、已领取条目不能编辑、会话删除清理及存储关闭时拒绝接受且不调用模型。

## 失败定位与修复

最初图片夹具上下文容量 10,000 token 不足以容纳项目对图片的 8,192 token 预留及输出预算，导致请求被正确拦截；夹具改用 20,000 token 模型，保留恢复正文和图片的断言。

终端失败明确发生在关闭管理器后的再次打开。测试紧接独立 Esc 输入 `/tasks`，可能在终端转义缓冲期组成 Alt+/；另一连接 RPC 返回不代表 UI 已处理 Esc。改为等待实际主输入栏 `Enter send` 再输入，保留所有导航、关闭不发送及仅执行一次断言，未增加超时。返回层级代码无需改动。

最终核对还发现 RPC shutdown 的取消路径会删除尚未确认的恢复记录，现显式区分退出保留与用户取消，并由同一个 PTY 脚本验证正常重启保留。

## 边界

这是待发消息恢复首切片。未答问题、steering、执行中的操作恢复仍待办。领取后、执行前崩溃的消息不在待发队列中，应核对未知回执与实际结果，不自动重试。本地 demo/fixture 不代表真实模型账号、真实图片解码、物理终端 IME、断电任意时点及长期多端竞争验收。普通 TUI 共用恢复实现，但本轮真实 PTY 验证限定为附着入口。
