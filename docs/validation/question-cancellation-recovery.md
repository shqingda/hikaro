# 问题取消保存失败恢复验收

日期：2026-10-23。对应 [规格](../specs/question-cancellation-recovery.md)，接续 `69c13b2` 的普通 TUI 问题恢复。

原取消等待结束、但取消记录未保存时，不再要求重启。服务为确实由本实例保存并取消失败的问题保留内部恢复资格，绑定原会话、执行会话和 scope；原实例 ID 与持久 JSON 保持不变。普通 `/questions` 和附着面板重新呈现恢复问答，答案只保存为上下文，原工具等待仍然结束。

SQLite 只增加内部事务参数，没有表迁移或客户端可控恢复参数。恢复仍检查 pending 状态、原身份、工作区、当前控制权限和无活跃租约；答案、审计和完成状态一次提交。恢复取消只记审计，不添加上下文。失败或租约拒绝保留恢复资格，等待用户显式重试。

取消开始同步标记原等待；提交保留最初等待对象的引用，读取返回后检查是否发生取消。因此旧回答不能在取消保存期间继续按正常回答提交，也不能在取消失败之后自动升级为恢复回答。先确认授权 pending 存在，再返回生命周期错误，避免向其他身份透露该问题的取消状态。

附着界面识别同一 ID 的恢复状态变化并关闭旧面板；清理按控制器归属，旧回调不会清除新面板。即使保存发生在轮询之间，成功提示也依据实际响应，明确没有恢复旧操作。
