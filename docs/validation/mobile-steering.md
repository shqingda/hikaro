# 手机补充指令与队列管理 · 2026-10-21

手机可明确选择普通发送或补充到下一模型轮；后者不启动新任务。原文、方法和命令 ID 先持久化，丢回执后只查询，不自动重发。旧版普通发送草稿默认仍为 prompt。独立管理模块复用现有 host 协议，提供全文查看、编辑、置顶、删除与原身份恢复确认；主机仍重新校验任务和控制权限。

## 自动验收

- `tests/mobile-composer.test.ts`：7 项通过，新增 steer 方法保存、应用重建和旧记录兼容。
- `tests/mobile-steering.test.ts`：5 项通过，覆盖续期/关闭释放、晚到锁释放、任务变化、落盘等待后的权限复核、失败编辑保留、不自动重试、过期锁及续期期间持续编辑。
- `tests/mobile-controller.test.ts`：4 项受影响定向用例通过，包含原有发送、离线草稿和控制权回归，以及新增 steering 实际 host 场景。本轮合计 16 项不同用例，后续相关复跑不累加。
- 唯一自动 E2E 文件仍是 mobile-controller：实际 shared host、SQLite 和加密 socket fixture。启动前写入持久恢复项，验证原身份确认、外部身份拒绝和确认后不启动；发送三条 steering，编辑、置顶、删除，再丢弃第四条回复并重建 controller。核对总计四个 steer 帧、明确 prompt 前没有 prompt 帧；明确开始后，历史顺序及原文正确，各消费一次，外部未确认项不消费。这里是恢复数据库启动，不声称本轮执行了 host SIGKILL。
- 最终根目录和移动端类型检查通过；iOS/Android Hermes 导出通过，分别 1612/1584 个模块，bundle 均约 4.3 MB。移动端修改未触及 CLI，未重复 CLI 构建、全量测试或性能基准。
- 审查临时移除管理器控制权限判定，定向测试按预期失败；已逐字节恢复原文件。没有降低门槛、删断言或增加超时。

最初新增测试分别因提交类型/模块尚未实现按预期失败。集成 fixture 首次因 macOS `/var` 与 `/private/var` 工作区路径不同失败，改为使用 realpath 后通过。原生编辑时发现每 5 秒续期会设置 loading，暂时禁用编辑器；新增测试复现后，将续期与界面刷新分开，5 项模块测试及受影响 host 集成复跑通过。

## 原生 iOS 验收

在 Codex 内置浏览器 `http://localhost:3200/` 操作现有 iPhone 18 Pro／iOS 27.0 原生开发客户端。隔离测试使用 shared host、SQLite、Miniflare TLS relay、demo provider 及官方 cloudflared 临时 HTTPS 隧道；证书校验保持开启，没有安装 CA、创建或重装设备，也没有启用系统辅助功能权限。该网络环境不等于生产 relay 或真实模型验收。

1. 粘贴中文两行与 emoji，点击“补充到下一模型轮”。host 队列保存完整原文且仅一份，输入框清空，没有自动启动任务。
2. 打开队列、查看全文、点击“移到最前”，host 顺序核对正确。
3. 删除另一条隔离测试指令：先取消确认，随后再次打开确认并删除。原生列表及 host 均只保留手机指令，见[删除后](../design/mobile-steering/queue-after-delete.png)。
4. 管理页打开时从测试电脑提交普通要求，确认历史尚未出现它；点击“关闭并返回任务”后继续运行。普通要求和手机补充原文各出现一次，队列为空；原生任务页也显示这些消息，见[释放后](../design/mobile-steering/after-release.png)。
5. 撤销测试设备，App 显示配对失效。host、relay、临时隧道已停止，测试剪贴板已清空，临时目录移入废纸篓；原有模拟器、Metro 及 Codex 预览保留。
