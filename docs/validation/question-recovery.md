# 未答问题跨 host 恢复验收 · 2026-10-20

## 本轮实现

独立 host 的 `ask_user` 在展示前保存问题、执行会话、审批归属会话、来源身份和 host 实例。重启后附着 TUI 沿用原 `--client-id` 可重新回答，标题明确标记 Recovered question。正常 host 关闭保留未答记录；明确取消保留取消审计，不推断答案。

提交时再次检查原身份、当前会话、远程控制权限和记录状态。恢复答案、问题上下文及完成状态在同一 SQLite 事务提交，重复回答不会生成第二条消息。原执行租约未到期或会话正在其他位置执行时拒绝恢复提交；界面保留本次答案并允许手动重试。未答记录不会因提交失败删除。

恢复不续接旧工具 Promise，不重放旧操作，不发起模型请求，不解除 Plan 只读。答案保存后提示用户发送新消息继续。正常实时问答仍返回原工具调用；其提交记录持久保存为 `question.response` 审计事件。

## 验证结果

- `pnpm test tests/question-recovery.test.ts tests/attached-workflows.test.ts tests/question-recovery-pty.test.ts`：3 文件、5 项通过。
- 新增权限/关闭/取消用例后，`pnpm test tests/question-recovery.test.ts -t "rechecks current remote control rights"`：该项通过；另一项因过滤未重跑，不是删除或禁用测试。合计 6 项不同用例通过。
- `pnpm typecheck`、`pnpm build` 通过；随后新增的测试再经类型检查。
- 无全量测试、全量 E2E 或性能基准。

唯一真实 PTY 用例使用本地 SSE 模型夹具生成 `ask_user`，通过独立 host 持久保存后 SIGKILL。新 host 保留原问题，测试等待原 30 秒执行租约自然到期，没有修改租约。附着 TUI 回答并审阅提交后，核对模型请求仍只有一次、答案恰好保存一次；发送新消息后才出现第二次模型请求，且请求包含恢复答案。Plan read-only 保持可见。

核心测试覆盖原身份恢复、错误身份/会话、重复提交、活动租约拒绝、答案上下文留存、Plan 状态、当前远程角色从 view 到 control 的重新校验、正常关闭保留和显式取消持久化。

开发时首次新增测试按预期因缺少持久接口失败；实现后问答测试通过。类型检查发现 `randomUUID()` 默认参数被推断成 UUID 模板字面量类型，显式声明 host 实例参数为 string 后修复，未放宽测试断言或超时。

## 边界

本轮覆盖独立 host 与附着 TUI。普通非 host TUI 的问题持久化、未提交答案草稿、自动续跑、跨身份接管仍未实现。旧租约可能使恢复提交等待最多约 30 秒；活动新执行也会阻止提交。对子任务的问题，将答案保存到审批归属会话并注明中断，不自动恢复子任务。

本地 SSE 和 PTY 验证不代表真实账号、断电任意时点、物理 IME 或长时间多端竞争验收。存储表保存已处理状态与审计，随归属会话删除清理；不据此宣称已有完整历史执行查询界面。
