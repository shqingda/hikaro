# 手机本机存储初始化重试 · 2026-10-23

原 `nativeStorage` 缓存初始化 Promise，包括永久缓存失败结果。首次打开 SQLite、设置表结构或清理首次安装遗留 Keychain 时失败，之后“重新连接”仍只能拿到同一失败，必须杀掉 App 才有机会恢复。

现失败后允许重新初始化，且先释放部分打开的数据库。独立审查核对 Expo SQLite 58.0.13 原生实现后补齐关闭失败边界：SDK 会缓存连接并恢复引用计数，因此保留尚未关闭的 owner，下一次先重试关闭，成功后才重新 open，不累积 native 引用。并发调用共享同一次初始化与清理，不各自重复打开。

首次安装安全规则保留：先成功删除遗留 Keychain 身份，再写 installation 标记；清理失败不读取或返回旧身份。没有降低 SecureStore 保护、修改 WAL/FULL 或放宽持久化校验。

`tests/mobile-native-storage.test.ts` 六项通过：打开失败重试、表结构失败清理、首次安装 Keychain 锁定恢复、并发共享、关闭持续失败不重新打开、关闭未完成时后续调用等待。原始四用例全部先失败；审查追加的关闭失败用例也先失败后修复。移动类型检查通过。

测试直接加载实际存储适配器，用可控替身代替 Expo 原生 SQLite/Keychain 模块以注入失败；不声称注入过真机 Keychain 锁定或完成真机存储压力验收。Node 测试动态导入 native 适配器，避免把 React Native 全局声明混入主机 TypeScript 项目；移动项目自身仍执行完整类型检查。
