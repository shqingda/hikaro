# 手机默认接续与命令补全修复 · 2026-10-29

## 用户反馈与实际处理

用户截图显示手机已经连接，但 `hi` 任务未共享；此前 `/permissions` 仅配置模型工具权限，不能改变手机任务授权。本轮已按用户明确指令，为其当前 `hi` 任务开通 control，并将默认产品行为改为“确认自己的手机后直接接续工作区任务”。无需重新部署 Cloudflare 中转。

## 实现

- 已确认手机默认控制当前工作区所有已有与新建会话，可发送、审批、停止；存量已确认设备同样适用，不要求重新配对。逐请求配对校验、工作区隔离、显式 `view/off`、设备撤销及本机管理边界保留。
- 连接后先读取第一页会话，有会话显示列表；没有则自动创建一个并打开输入框。列表增加新建任务，重连/刷新/空分页不重复创建，丢失回执不自动重放，旧草稿先保存且不自动发送。
- `/permissions` 等候选重复来自基础与附着命令直接拼接；补全入口按名称合并，后传入定义覆盖基础定义，保留参数补全和扩展命令。
- Android 本地构建使用 Expo `--no-clean` 保留原生工程与 Gradle 缓存，仍通过公共预检、正式 Release 编译、原签名证书和 zipalign 校验。此前每次清空工程造成重复编译，已有两轮构建日志证明该成本。

## 证据与边界

- 真实加密设备/共享宿主回归覆盖无需逐任务 grant 的已有/未来任务访问、发送、审批、停止、未确认拒绝、显式只读与拒绝、设备撤销、问答和草稿。
- 移动端回归覆盖首次连接、历史列表、空会话自动创建、分页空页、丢失创建响应、重连和草稿；TUI 测试覆盖实际候选显示及 Tab 补全不发送。
- 四处旧测试预期已更新：需拒绝的任务明确设为 off，而非以“缺少 grant”表达拒绝。原有只读、历史不可审批、断线/重启恢复等负向检查保留。
- 现有 iPhone 18 Pro 模拟器检查实际 Tasks/Task 组件浅深色：`artifacts/validation/mobile-start-20261029/ios-first-session-{light,dark}.png`、`ios-sessions-{light,dark}.png`。截图用合成控制器状态；临时页面已删除，不代表 Android 真机验收。
- 完整本地预检与 APK 构建日志：`artifacts/validation/mobile-start-20261029/android-release.log`，完成后补记产物。

存储不改表结构，但新增显式 `off` 取值语义；旧二进制不能安全理解该值。回退须恢复升级前数据库备份，不能直接用旧版打开含新拒绝项的数据库。详情见 [ADR-002](../decisions/002-personal-phone-control.md)。
