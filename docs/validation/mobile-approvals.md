# 移动端审批与回执 · 2026-10-21

## 行为

手机任务页可展开完整审批原因、参数和文件访问范围，明确允许或拒绝本次请求。仅在线、持有当前任务 control/owner 权限且审批仍有效时发送决定。host 继续复核身份、任务与授权，其他设备抢先处理后不能再次消费同一请求。

操作等待期间阻止重复点击和切换任务。失败和过期都显示可读提示；收到决定不等于工具执行成功。手机展示本设备最近审批回执，重连及手动核对只查询原命令状态，不重发审批。后台隐藏审批内容，旧连接的迟到结果不能覆盖新连接。

## 本轮证据

- `pnpm exec vitest run tests/mobile-controller.test.ts`：7 项通过。
- 实际 `serveSharedHost`、SQLite、IPC 与 `dispatchRemote`：电脑/手机并发批准仅一方成功，工具实际写文件；重复旧审批拒绝；丢失拒绝回执后重连核对，审批帧仅发一次；control 降为 view 后不能继续操作。
- controller 定向覆盖：只读权限、过期请求、重复点击、后台清除、错误提示；保留已有长消息和生命周期回归。
- `pnpm mobile:typecheck`、`pnpm typecheck`：通过。
- `pnpm --filter @hikaro/mobile export`：iOS 4.3 MB、Android 4.2 MB Hermes 生产 JS 导出通过，日志保存在忽略目录 `artifacts/mobile-m1-export.log`。

真实 host 用例首次暴露一个回执展示问题：断线中的历史读取也被计为“结果未知的操作”，且读请求不参与持久操作核对。现使用协议的只读方法集合排除读取回执；原断言保持，修复后通过。
