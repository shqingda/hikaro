# ADR-002：配对自己的手机即允许接续工作区任务

## 状态与日期

Accepted · 2026-10-29。用户明确要求：自己的手机确认配对后即可发消息、审批和停止，不再逐个任务手动授权。本决策替代此前“配对仅建立设备身份，所有旧任务另行 `/share`”的默认流程；连接方案与 Tailscale 暂缓决定不变。

## 决策

- 在电脑确认手机并完成加密握手后，该设备默认获得当前共享 host 工作区内已有及未来任务的控制权。已确认的存量手机升级后沿用该规则，不要求重新配对。
- 未完成确认、配对过期或已撤销的设备不能访问任务。宿主继续逐请求检查设备状态与任务归属，不能跨工作区访问。
- `/share DEVICE view|control|off` 保留为主动限制/恢复某个任务的高级入口。显式只读与禁止访问覆盖默认控制权，不会因重连或创建其他任务丢失。设备不能自行解除限制。
- 模型工具执行权限仍由 `/permissions` 管理，宿主设置、设备授权等管理操作仍限本机 owner。拥有手机任务控制权不等于自动放行所有工具。
- 首次连接取得第一页历史后，有会话则显示列表；没有则自动新建一个并打开对话输入框。列表提供“新建任务”。分页空页和刷新不触发自动新建，重连先恢复主机状态，草稿始终显式发送。

## 原因与边界

旧流程把“设备已连接”和“任务不可见”并列呈现，用户已配置模型及工具权限仍只能看到空列表。个人手机的日常接续不应要求复制长设备 ID 为每个任务再授权一次。配对确认面板直接说明控制范围，使确认动作与实际能力一致。

保留显式任务限制和整台设备撤销，不引入新的账号体系、角色管理 UI、推送实现或数据库表迁移。现有存储里过去的 `off` 表示删除授权记录，无法区分“从未授权”与“以前取消授权”；此次按用户明确指令切换默认访问规则，后续显式 `off` 会持久保留为拒绝项。

## 同批修复

TUI 基础命令与附着命令直接拼接导致 `/permissions` 等候选重复。自动补全入口按命令名合并，后传入定义覆盖基础描述和参数补全，保留扩展能力。

实现、自动检查、模拟器视觉与用户真机验证分别记录，不互相替代。无需改动或重新部署 Cloudflare 中转。通知和 Tailscale 继续暂缓。

回退边界：新的显式拒绝项使用现有授权表的 `off` 值，不修改表结构，但改变了该列的取值语义。旧版程序不能安全解释该值；回退到本改动之前的二进制必须恢复升级前数据库备份，不能直接打开含新拒绝项的数据库。沿用项目已有备份回退流程，不新增迁移框架。
