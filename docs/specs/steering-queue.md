# Steering 队列管理

`/tasks` 增加 Steering messages 类别，显示尚未被模型轮次消费的补充要求。支持稳定 ID、全文阅读、编辑、提前及确认移除。管理器打开期间不消费 steering，正在进行的模型请求/工具继续；若当前轮已结束且仍有 steering，则等待管理器关闭再开始下一轮。取消运行会中止等待并清空队列；撤销来源身份清除其 steering。

沿用附着会话控制权限，过期 ID 明确报错。普通与附着共用面板。不改变待发 prompt 与 steering 的语义：steering 属于模型下一轮上下文，不是新任务。

## 持久化与恢复

运行时收到补充指令后，先将稳定 ID、原文、来源身份和顺序写入 SQLite，成功后才回复接收。编辑、提前、移除同样先落盘；每会话最多 16 条，每条最多 100000 字符。删除会话同时删除补充指令。

host 重启后全部未消费记录标为待确认，关闭面板、发送另一条 prompt 均不自动消费；原来源身份确认后才加入下一模型轮。空闲时确认不会启动任务。再次重启仍需确认。正常关闭保留未确认的恢复项；取消清空所有待处理项，撤销仅清除该来源。

消费须持有有效会话租约；删除记录和将其原文追加到对话历史处于同一 SQLite 事务，成功后才发布事件。并发编辑以事务读到的保存原文为准。已写入历史的指令不会再次出现在恢复列表中，但中断任务仍按现有 unknown 语义等待明确的新请求。

接收写入与取消/撤销并发时，以取消代次阻止晚到写入重新变成可执行项。删除失败保留可见原文和错误，隔离为待确认，不能继续自动消费；操作错误不能用成功回执掩盖。存储失败不会触发自动重试模型调用。

验证：steering-queue 核心测试、execution-panel、attached-workflows 定向测试；唯一 steering-queue-pty 覆盖附着终端编辑/提前/移除与实际模型接收顺序；类型检查及构建。
