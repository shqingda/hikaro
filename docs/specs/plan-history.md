# TUI 计划历史版本浏览

日期：2026-10-23。本规格补齐 planning-dialogue 首切片中未交付的历史版本浏览，不改变当前计划的批准语义。

## 入口与行为

普通及附着 TUI 使用 `/plan history`，展示本会话已保存计划，最新在前，每页最多 20 条。列表显示稳定的保存顺序编号和标题；选择后以只读文档面板阅读原始标题、步骤和验证要求，支持上下滚动、返回列表和翻页。历史页面没有批准、执行或恢复当前计划的操作。读取历史不进入 Plan 模式，也不发送模型请求。

当前计划仍由 `/plan` 审阅。批准须再次核对当前计划 ID 和 active 状态；读过或选中过历史版本不会使其获得执行权限。

## 保留与迁移

原实现仅保留当前计划，生成新计划、重新进入或退出 Plan 会覆盖它。因此无法恢复本功能启用前已经丢失的版本。

新增计划正文保存到私有 `plans/<会话哈希>.json.versions/<计划UUID>.json`。当前状态文件保留按保存顺序排列的 UUID 索引，不包含历史正文。列表编号表示该索引中的保存顺序，不推测旧版本的原始编号或生成日期。

旧格式当前计划仍可直接阅读。在下一次修改状态前，将它保存为独立版本；旧格式状态标记历史不完整，界面明确提醒更早版本没有保留。新生成的计划也先写入独立快照，再更新当前状态及版本索引。

快照先完整写临时文件，再用同目录硬链接独占发布到 UUID 路径，避免半写内容成为可读版本。已有版本只允许内容完全一致的重试，不允许覆盖。当前状态沿用临时文件加 rename；只有进入当前状态索引的快照才出现在历史列表中。中断留下的未索引快照不被当成已提交版本；随会话删除清理。同会话刷新串行化，读取前捕获本地写入代次；读取期间发生保存或删除时，迟到读不得覆盖缓存中的已提交状态。此流程不增加跨进程并发写入权，继续依赖 Runtime 原有会话操作锁和执行租约。

取消和批准保留历史。删除会话时同时清理状态和版本目录。派生会话仅沿用原有行为：重新提交父会话当前计划为子会话自己的版本，不复制整个父会话历史。

## 协议及边界

新增只读能力：

- `plan.history { sessionId, before? }`：最多 20 条 `{ id, title, revision }`，返回 `nextBefore` 和 `incomplete`。`before` 是严格正安全整数，取编号更小的版本。
- `plan.version { sessionId, id }`：返回该会话索引中的一个完整计划；ID 必须为 UUID。正文受现有 proposal schema 限制：标题 200 字符、最多 12 个步骤且每步 4,000 字符、验证要求 4,000 字符。

两项方法加入 capabilities 和只读方法集合，沿用所选会话约束及 host 的 view/control/owner 授权。未经授权、跨所选会话、撤权后的读取均失败；历史 ID 不能跨会话读取。附着端检查能力，旧 host 明确要求升级。连接或会话变化沿用附着工作流代次保护，迟到结果不用于后续操作。

验收必须覆盖持久保存、旧格式迁移、分页、删除清理、旧 ID 批准拒绝、view 只读授权、普通及附着真实 PTY 的完整入口和无执行终态。真实账号、物理终端、逐步骤执行进度及超大历史性能保持独立验收。
