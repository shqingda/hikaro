# 待发消息崩溃恢复首切片

普通与附着 TUI 的 `/tasks` 保留尚未派发的正文、图片、顺序和来源身份。SQLite 提交成功后 host 才确认接受；派发前原子删除待发记录，故删除后崩溃可能保留未知回执，但绝不自动重放。

Runtime 打开会话时将存储记录载入为「待确认恢复」。打开、关闭管理器或发送其他消息不释放这些记录。用户可编辑、删除，或确认恢复发送；附着操作仍检查当前会话控制权限，并且只能恢复属于当前来源身份的消息。恢复不继承旧审批。正常取消清除待发记录，正常关闭保留尚未确认恢复的记录。

本轮不恢复未答问题、steering、执行中的消息，也不把旧 RPC 未知回执改成成功。恢复动作采用新的明确用户意图，旧回执仍供核对。存储失败必须阻止派发并显示错误。会话删除同时清理记录。

验证计划：`tests/pending-message-recovery.test.ts` 验证持久保存、重新打开、确认前不派发、身份检查、编辑/删除和一次性领取；`tests/execution-queue.test.ts` 验证原队列管理；一个 `tests/pending-message-recovery-pty.test.ts` 验证真实 host 强退与附着 TUI 恢复入口。最后类型检查和构建。不运行全量测试或性能基准。

验收结果与故障定位见 [待发消息恢复验收](../validation/pending-message-recovery.md)。本轮真实终端覆盖附着入口；普通入口复用同一核心与面板，不据此声称已单独完成普通 TUI 崩溃 PTY 验收。
