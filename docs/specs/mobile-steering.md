# 手机补充指令与队列管理

手机草稿可以明确选择发送普通要求或补充到下一模型轮。后者使用现有 `steer`，不新建运行；草稿持久保存提交方法与命令 ID，恢复只查询对应方法的回执，旧版本普通 prompt 草稿保持兼容。

任务页打开“补充指令队列”，只对在线且具有当前任务控制权、支持相关方法的 host 开放。管理期间用现有 execution hold 暂停 prompt 分发和 steering 消费，每 5 秒后台读取续期，不改变编辑器的加载状态或原文；列表由显式刷新更新。离开、后台、断线、切换任务或撤销权限立即废弃本地 token，尝试释放，无法通信时由 host 在 15 秒到期后释放。只在页面打开时续期。

列表最多 16 项，详情读取全文后才能编辑、置顶、删除或确认恢复。删除和恢复使用原生确认框；恢复明确提示仅适用于原身份，不启动新任务。主机再次校验身份、任务与控制权限。失效锁、已消费项、晚到读取和丢回执均保留可见错误，不自动重复操作；编辑失败保留屏幕原文，退出编辑有放弃确认。重新打开重新取得管理锁。

独立 MobileSteering 负责锁、读取及操作生命周期，MobileController 只绑定当前连接。使用已有原生控件和导航，不增加依赖，不复制 host 队列或在手机自动执行恢复项。

验证：composer 保存提交类型且兼容旧数据；管理模块验证续期/释放、晚到锁、任务与权限变化、失败编辑保留及无自动重试；mobile-controller 实际 host 用例覆盖发送、编辑/排序/删除、原身份恢复和重建连接不重复发送。必要类型检查与双平台导出后审查提交。原生键盘/IME、Android 和真机验收继续单独保留。
