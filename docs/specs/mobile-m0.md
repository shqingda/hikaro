# M0 — paired read-only mobile companion

Scope (2026-10-18): a native Expo app for iOS/Android, connected to the existing shared host through the authenticated encrypted relay adapter. Scan or paste an unexpired pairing URI, confirm host/relay/device identity, securely persist credentials, then restore only explicitly granted sessions, messages and active output. Do not add task creation, prompt/steer/cancel or approval responses in M0. `session.resume` changes only this device's selected view and must use durable intent IDs.

Trust boundaries: QR/links, relay frames, restored credentials and RPC pages are untrusted; pinned host key and existing mutual challenge remain authoritative. Use system secure storage for device secrets, no credential/URI/body logging, no plaintext credential fallback. Persist only bounded ID/method intent metadata in SQLite (WAL/FULL), isolated by relay + host key/ID + device. History is bounded in memory, never persisted or automatically displayed as fresh offline state. Foreground restoration begins with hello/snapshot and receipt reconciliation, never mutation replay. Background releases the connection and obscures task content; only an explicitly user-selected pairing is enrolled. Revocation/authentication failure locks the view, removes credentials and scoped intent state, and does not silently reconnect as another identity. Ordinary transient network loss retains a visibly stale view and retries safe reads only.

UI: connection/pairing page, QR scanner, granted task list, read-only task detail. Native navigation/controls, text scaling, selectable output, visible loading/error/empty/offline states, pagination and bounded streaming updates. Camera denial retains paste pairing. No credentials in route parameters or navigation history. Enrollment system deep links are deferred; only in-app QR/paste can import a pairing. Native storage/runtime validation is distinct from JS fixture verification.

Evidence: necessary controller/credential validation and lifecycle race tests; real shared Runtime/SQLite + encrypted adapter integration proving read-only boundaries, reconnect/recreated app, lost selection acknowledgments and revocation. Native iOS simulator runtime plus iOS/Android production JS export/type checks; actual physical devices, camera scan, release performance and Android runtime are recorded honestly when unavailable. Try Expo Go first, use a development build when the current SDK/runtime requires it.

Performance: retain standalone TUI 30 launches/3 warmups, startup p95<=200ms, input<=16ms, RSS<=100MiB; retain all 10k core/storage assertions and budgets. Measure shared host+TUI combined RSS before and after under the same sampler (H1 ~126MiB, not an accepted new budget). Profile first; keep only measured memory improvements without weakened validation/durability/workload. Mobile targets remain release startup<=1.8s, input<=16ms, incremental display<=50ms, footprint<=140MiB and 30-min growth<=10%; do not substitute debug/simulator numbers for these acceptance gates.
