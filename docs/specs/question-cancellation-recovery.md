# 问题取消写入失败后的同进程恢复

共用问题服务在取消开始时同步标记正在结束的等待，禁止已读入旧状态的回答继续按正常问答提交。取消记录保存失败后，原工具等待仍结束，不接回旧 Promise；服务只为确实由本实例提出、已保存且取消写入失败的问题保留内部恢复标记。标记绑定问题 ID、审批归属会话、scope 和原实例。

用户重新打开 `/questions` 或附着问答面板时，显示恢复提示。恢复标志由服务内部产生，RPC 请求不能指定。SQLite 在原事务中重新检查 pending 状态、身份、工作区、控制权限和无活跃执行租约；恢复答案与问题上下文只保存一次，恢复取消不增加用户消息。不改持久问题 JSON，不迁移数据库，不修改原实例 ID。

附着界面识别同一问题从正常问答转为恢复状态，使旧面板失效并显示恢复说明；面板清理按控制器引用核对归属。若状态在轮询之间变化，保存成功提示依据实际响应中的恢复结果，明确说明只保存上下文。

租约或保存失败时保留恢复资格，允许用户显式重试；成功后清除内部标记。无法确认落盘结果时仍以数据库 pending 状态为准，不自动重试，不重新启动工具、模型、队列或子代理，不改变 Plan 模式。

验证先覆盖取消保存失败后的原等待结束、同实例恢复、错误身份/会话、权限变化、活跃租约、重复提交和伪造 RPC 恢复参数；再用延迟读取制造回答跨过取消窗口，验证旧回答被拒绝。真实 UI 沿用上一片普通与附着恢复入口，不新增自动恢复行为。

证据与限制见 [验收记录](../validation/question-cancellation-recovery.md)。
