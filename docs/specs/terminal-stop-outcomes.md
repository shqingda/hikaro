# 后台终端停止终态

Unix PTY 使用 forkpty 创建独立会话/进程组。停止时发送进程组 SIGTERM；最多等待一秒，仍存在则发送 SIGKILL，并限时核对进程组消失。收到主进程 exit 不等于清理完成；必须同时确认退出事件与进程组清理后才显示 exited。失败显示 stop_failed 和原因，提供重新停止；正常停止请求保持 stopping。

保留实际退出码和信号，terminal_read 与 `/tasks` 使用同一状态。插件关闭等待所有停止结果，不能先清掉记录或把请求当成功。该范围不保证清理自行 setsid 脱离进程组的 daemon；不会扫描并杀死任意系统进程。

验证：真实子进程忽略 SIGTERM、主进程先退出的 terminal-stop-outcomes 测试；已有 execution-terminal/terminal-cancellation 定向用例；唯一 execution-control-pty 实际停止界面流程；类型检查与构建。

## 已观察后代（macOS）

后台 PTY 启动后、停止前后、主进程退出时读取一次后代快照，仍有已知进程时每秒刷新。原生 helper 只按父子关系查询，记录 PID 与启动时间；首次根必须是当前 host 的直属子进程，后续只接受完整身份匹配的进程。身份失配或进程消失后不凭同一数字 PID 重新跟踪。最多访问 256 个节点、向下 16 层；helper 超时 1 秒，输出最多 128 KiB。快照只读，不枚举全部系统进程，也不发送信号。

原始进程组清理和后代观察分别表达：主进程退出后仍观察到后代，显示 `descendants_running`；保留的后代身份暂时无法核实，显示 `descendants_unknown`。二者均不提供发送或停止按钮。`cleanup: confirmed` 只指原始进程组，详情明确说明此边界；确认进程组消失后不再向该数字 PGID 发信号。已知后代存活或未确认消失时计入 8 个终端上限，避免轮询与记录无限增长。

快照可能漏掉两次采样之间创建并脱离的进程，不声称完整 daemon 包含或清理。读取失败、权限不足、数量/深度超限标记观察不完整；非 macOS 标记不可用。前台 Shell 脱离探测与跨平台原生探针后续处理。只持久化最多 4,096 字符的人类可读摘要，不保存可恢复的控制身份；重启后摘要明确为历史观察，不重新探测或操作旧 PID。移动端沿用只读任务详情，不增加控制入口。
