# Plan 与结构化提问

普通 TUI `/plan TASK` 进入只读探索；`/plan` 查看当前模式/审阅已生成计划。模型使用 ask_user 提交 1–3 个结构化问题，方向键选择预设答案或输入自由回答，全部回答后提交；Esc 取消，不构造默认答案。submit_plan 保存带版本号的计划，模型结束后自动打开审阅。审阅支持分页、要求修改、保持只读、确认执行。确认仅绑定当前版本，过时版本不能执行。

Plan 状态和计划私有持久化；重启后未批准计划仍只读，不自动执行。原生 read_file/list_files/search 才能用于探索；禁用 Git（可能触发仓库过滤器）、Shell、写入、Terminal、插件、codemode、委派和调度。策略在每次 Agent.invoke（含嵌套调用、手动 !）检查，Full Access 不绕过；工具身份绑定，不能用同名插件替换白名单。所有请求携带只读提示并只公开允许工具。日志、快照、会话持久化属于应用自身存储，不承诺整个操作系统只读。

进入/批准/退出要求会话空闲、无待发消息，且当前会话无运行终端/子任务；确认后由 TUI 显式发送已批准计划执行请求。运行中的 Plan 不能通过回退接口修改工作区。取消计划需确认且不启动任务。切换会话读取该会话独立状态。附着 TUI 后续补齐，不通过接口存在宣称交付。

按测试驱动顺序：只读边界与持久计划 → 问题/审阅面板 → CLI 路径 → 一个真实 PTY（本地模型 fixture）验证读文件、结构化回答、计划修改/取消、确认后写入。定向测试、类型检查、构建；遵循 TODO 的两轮修正规则，不跑全量或基准。

## 使用和交付边界

`/plan TASK` 开始探索；`/plan` 审阅当前计划或进入只读模式；`/plan cancel` 二次确认后退出，不执行任务。回答页支持返回与修改，汇总后显式提交。计划审阅默认保持只读，批准后仍遵守当前权限模式，Ask 模式后续工具照常审批。计划版本在批准时再次核对；正常重启不自动派发执行。

当前仅普通 TUI。保存的是最新计划，没有版本历史浏览或逐步进度勾选；未回答的问题在强退后不自动恢复或自动作答。已完成模型请求和最终结果使用现有会话历史；计划文件目前不随会话删除清理。

只读限制针对本 Runtime 的 agent 工具与 TUI 操作，不是操作系统沙箱。已经加载的第三方 JavaScript、插件初始化、外部进程和其他会话不是此策略能隔离的执行环境。Plan 中不派发 agent 插件事件，禁用插件命令/视图，禁止切换时仍有本会话活动终端/子任务。读取白名单不包含 Git，以免触发仓库过滤器。

定向验收见 [Plan 验收](../validation/planning-dialogue.md)。
