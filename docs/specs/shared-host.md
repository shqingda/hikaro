# Shared host — H1

Status: implemented and locally verified (2026-10-18). Native mobile UI/storage and physical-device acceptance remain M0. See the [startup/recovery guide](../shared-host.md).

One opt-in `--host` process owns a canonical workspace + data-home pair. `--attach` renders the existing TUI against that host; `--serve` bridges authenticated remote devices to the same endpoint. Standalone TUI retains its measured startup path. No automatic service installation, privilege escalation, or native mobile app is part of H1.

Local IPC uses an owner-only Unix socket directory, socket and bearer metadata, with bounded JSONL input/output and per-connection scope injection. A transactional SQLite host claim checks the owning PID before removing an abandoned endpoint; two live hosts must not both own the same workspace. A missing or unsafe endpoint fails closed. Socket loss detaches a view, never shuts down its host or replays a mutation.

Shared mode explicitly authorizes sessions: local owner clients may manage grants; paired devices retain ownership of sessions they create but require a persisted view/control grant to join another session. Only control participants viewing that session receive its approvals. The host rechecks membership and request identity before applying a response; a resolved/stale request cannot apply twice. Revoking a participant removes that view/approval access without denying another participant's still-pending decision. Device revocation also cancels that device's own work.

Selections and session grants survive host restart. A reconnected client handshakes, restores the authoritative snapshot and reconciles recorded command IDs. The attached TUI persists client intent metadata before sending mutations; portable/native clients can inject a durable IntentStore (native platform storage remains M0). Transport loss leaves unknown outcomes and never retries an operation. Reopened unfinished runs remain unknown. Local drafts remain explicitly unsent.

Necessary evidence: storage claim/access isolation; one real shared host with local + authenticated-remote adapter covering shared run, approval race/revocation and disconnect/restart; one PTY attached TUI flow. Keep existing RPC compatibility checks, portable typecheck, startup p95 <=200 ms, input <=16 ms, ready RSS <=100 MiB, and the unchanged 10k core/storage harness. Record the separate warm-host attach measurement rather than extrapolating standalone TUI numbers.

The same stable client ID has one active channel: a replacement fences the old socket and stops its automatic reconnect loop. Local view identities and authenticated 43-character device scopes cannot be exchanged by changing RPC fields. Shared-only access methods are excluded from ordinary stdio capabilities; stdio approval ownership remains compatible. Device revocation removes scoped queued prompts and steering without canceling another owner's active run on the same Agent. Shared prompt/steer/cancel recheck the selected Agent/session and control membership after durable acceptance, so a waiting control cannot act on a newly resumed view-only session.

Only live Runtime delegation can inherit a root session's approval authority. The presented permission keeps the actual child session ID plus host-assigned `authoritySessionId`; authorization, audience and final decision use that recorded root. Runtime tracks at most its bounded active delegation depth, removing the link on completion. Forks and arbitrary persisted parent IDs do not inherit access, and responders cannot choose authority by supplying RPC parameters.

Necessary evidence is in `tests/shared-host-storage.test.ts`, `tests/shared-host.test.ts` and the durable-intent case in `tests/client-connection.test.ts`. The real TUI case exits while an approval is open, reattaches to that same request, accepts another view's decision, then recovers an unsent multilingual draft after SIGKILL. The encrypted device fixture proves grant enforcement, simultaneous approval, disconnected approval recovery and device revocation. A separately spawned host is force-killed and restarted: selection and run ID recover as unknown, and run.start counts prove no replay. Invalid credentials and insecure metadata fail closed. No hosted relay, external provider or mobile-device result is implied.
