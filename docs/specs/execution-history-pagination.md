# 执行历史分页与精确查询

## 目标与边界

普通及附着 TUI 能查看当前会话全部已保留的运行记录，不再因为最近 200 条运行事件、最多 100 次运行的窗口而失去旧详情。本切片提供按时间翻页和精确运行 ID 查询，不提供全文搜索、后台终端或子任务的独立持久索引。

历史始终只读。没有结束记录不代表仍在运行或已经停止；运行完成不代表计划步骤完成。历史阅读不重放操作、不启动模型、不恢复旧任务。原有 `execution.read` 数组与最近历史兼容契约保留。

## 接口与存储

- 新增只读能力 `execution.history`：参数 `{ sessionId, snapshot?, before? }`，返回 `{ items, snapshot, nextBefore }`。
- 新增只读能力 `execution.history.detail`：参数 `{ sessionId, id, snapshot? }`，返回只读 `ExecutionItem`；没有匹配记录时明确报错。
- `snapshot` 与 `before` 为安全整数游标。首请求固定当前会话最大运行事件序号，之后仅查看该序号及以前的数据；刷新清除旧游标并重新取快照。`before` 是排他的序号上界。
- 单页最多处理 200 条源运行事件、返回 20 次运行；读取额外一条记录判断是否还有后页。每个运行在快照内的最新事件是唯一分页锚点；开始/结束事件按同一快照与 runId 配对，不从当前扫描窗口猜测完整性。
- 列表只返回标题、状态与 ID，`detail` 为空且不含动作。详情通过专用方法读取；即使字段需要 JSON 转义，列表也不能超过传输上限。
- 游标记录最后实际扫描的事件。达到 20 个运行时不能越过尚未处理的事件。空页仍可能有 `nextBefore`，只有它为 `null` 才表示没有更旧源事件。
- 精确 ID 查询限制为 1–128 字符，兼容已有非 UUID 的 ID。查询限定原会话和快照，不受最近窗口限制。
- 原 `(sessionId, seq)` 运行事件部分索引用于扫描。新增按 `(sessionId, json_extract(data, '$.runId'), type, seq)` 的部分索引用于配对与精确读取。首次升级建索引需要读取旧事件，须实测并记录规模和耗时，不能宣称无升级成本。

新方法沿用 host 会话归属与读取授权；只读角色可读，其他会话仍被拒绝。运行期间允许读取，不持有写租约、不暂停队列。参数校验失败和缺失记录使用现有 RPC 错误结构。

## 交互与结构

共享浏览器放在 `packages/tui/src/execution-history.ts`，普通和附着入口复用。`/tasks history` 打开分页，`/tasks history RUN_ID` 打开精确详情；直接入口不申请队列暂停。现有 `/tasks` 管理器历史分类进入同一阅读流程，管理器的原暂停语义明确保留。

列表提供上一页、下一页、刷新、按 ID 打开和关闭。详情只阅读，没有执行或停止动作。分页详情固定列表快照；主动按 ID 查询取当前已保留记录。取消、断连或切换会话后的迟到读取不能更新新面板。

附着客户端仅在 host 同时支持两个新方法时启用完整分页。旧 host 继续提供明确标注范围的最近历史；不能把旧窗口显示为完整会话历史。

存储与运行时沿用现有 TypeScript 类型边界及 SQLite worker；协议不引入 Node 依赖。新模块必须进入实际分发构建。无新依赖，不降低既有测试和性能门槛。

## 验收

先编写失败测试，再实现最小闭环。覆盖超过 200 次运行的完整遍历、跨页开始/结束配对、重复事件、空页、分页期间新增终态、旧运行精确查询、重启、跨会话拒绝、只读角色和旧 host 降级。普通及附着实际 PTY 读取旧记录；浏览前后运行事件数量不变，直接入口不申请队列暂停。

执行定向 Vitest、`pnpm typecheck`、`pnpm check` 与实际打包 worker 检查。记录旧库索引升级及查询计划；未测规模和真实终端条件继续保持待验。验证文件位于 `docs/validation/execution-history-pagination.md`。
