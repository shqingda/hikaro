# 会话工具产物的可移植导出

## 目标与范围

普通与附着 TUI 的 `/export` 在现有 Markdown、图片目录之外，保留当前会话已保存的工具输出，并明确列出无法打包的资源。复制 Markdown 及同名 `.assets` 目录后，产物链接仍可读取。

本切片只处理持久化 `tool.end` 中已知的宿主产物引用。它不读取消息正文或 Markdown 中的路径，不扫描工作区或产物目录，不重新请求模型，不读取任意外部附件。文本附件的历史内容继续保留在原消息正文中；图片继续使用原有导出流程。通用二进制附件、任意插件资源及手机分享导出不在此范围。

## 来源与隐私边界

目前 `ToolResult.data` 为 `unknown`，`saveArtifact` 会把整个工具结果写入 JSON。额外字段没有导出白名单，不能认为原始 JSON 全部属于用户可见内容，也不能因为文件位于宿主产物目录就直接公开所有字段。

- `.json` 产物必须解析为对象，要求 `text` 为字符串。仅导出新建对象 `{ text, isError? }`；`isError` 仅在原值为布尔值时保留。禁止展开原对象，禁止复制 `providerData`、任意 `data`、未知顶层字段或其他内部字段。
- 产物 JSON 中的 `data.artifact` 和 `data.process.artifact` 仅用于发现下述受信日志依赖，不进入投影后的 JSON。图片仍由消息中的既有图片字段导出，不从任意 JSON 深层对象提取图片。
- `.log` 为保存的用户可见进程输出，按原字节复制。用户可见的 `text` 与日志内容不做关键字猜测或内容删改；隐私边界是字段选择，不承诺识别正文中的用户秘密。
- 原有隐藏 thinking 偏好、消息 `providerData` 排除和图片媒体类型限制保持不变。新增功能不能借读取产物扩大消息或 provider 私有字段的导出范围。

## 固定快照与有界枚举

整个导出只获取一次当前会话的最大事件序号 `through`。消息与工具产物都限定 `seq <= through`，之后写入的消息和 `tool.end` 不进入此次导出。固定的是事件引用范围，不代表文件内容具有创建时校验值；清单记录本次实际读取并导出的内容。

存储增加内部工具产物引用分页方法，输入为 `{ sessionId, after, through, limit? }`。游标均为非负安全整数，单页最多扫描 100 条 `tool.end` 源事件。只投影序号、受限长度的工具名/调用 ID，以及 `result.data.artifact`、`result.data.process.artifact` 两个已知字段；不把整个工具结果跨 worker 传输。非字符串、过长或不合规引用保留明确的无效标记，不退回自由文本解析。

分页按照 `seq` 升序进行，游标指向最后实际扫描的事件。无产物引用的事件也推进游标；空结果页不能误判为历史结束。`hasMore` 依据剩余源事件判断。使用已有 `(sessionId, seq)` 索引限定会话、范围和扫描顺序；若实现需要额外索引，须记录查询计划和升级成本。

该方法仅用于宿主导出，不新增可让远程调用者任意指定宿主文件路径的 RPC。普通和附着 TUI 继续调用相同 runtime 导出入口；附着侧沿用现有会话归属与导出授权。

## 文件授权与依赖

抽取并复用 `artifact.read` 现有路径核验和安全读取约束。宿主主目录可以先规范化，但余下目录与文件必须通过已有 secure-file-helper 的无符号链接路径遍历。不得先对候选文件执行 `realpath` 再绕过该检查，不得降级为普通路径读取。

候选只允许当前会话的 `artifacts/<sessionId>/` 或 `outputs/<sessionId>/` 直属文件，并沿用现有文件名白名单：64 位小写十六进制加 `.json`，或 UUID 形状加 `.log`。跨会话、其他目录、路径穿越、目录、符号链接及异常引用明确拒绝。文件名不由模型文本决定，导出端使用事件序号和本次计数生成资产名称。

顶层两个已知字段都要处理，不能因第一个存在而忽略第二个。对于已授权、已成功读取的 JSON，只检查其 `data.artifact` 与 `data.process.artifact`，且只跟随同一会话内合法的 `.log` 引用。嵌套 JSON、任意对象递归及自由文本路径均不跟随；已知字段中发现不支持的依赖必须列出状态。最大依赖深度为一层，循环引用不能触发重复读取。

按通过规范检查的宿主引用路径去重。同一资源被多个事件引用时只读取、生成一次资产，各事件指向同一清单项；失败也记录一次明确结果。无效或过长引用不保留原始值，无法确定是否属于同一资源，因此按出现次数计入候选预算。先作为嵌套 JSON 被拒绝的资源，后来具有直接事件引用时仍可处理；它只计一个候选，且不扩大依赖递归范围。不同路径即使字节相同仍可分别列出，不把内容哈希用作授权依据。原 JSON 文件名是调用 ID 的哈希，不能当作文件内容摘要。

## 上限与缺失提示

工具产物采用以下独立预算；原消息和图片导出范围保持不变：

- 每件源文件最多 16 MiB，与现有安全读取能力一致；超过即不打包，不截断。现有进程日志最多可保存 50 MiB，因此 16–50 MiB 日志明确列为超过本次导出单件上限。
- 最多处理 100 个不同的候选引用，含嵌套依赖和失败候选。达到件数上限后继续有界枚举其余事件引用，逐项标记未打包，不再读取新文件或解析其依赖。重复引用已处理的资源仍可复用结果。
- 累计读取源文件最多 64 MiB，累计写入工具资产最多 64 MiB。每次安全读取的上限不得超过单件上限与剩余读取预算的较小值。投影后的 JSON 大小也须在写入前检查。预算不足时不读取或写入部分文件。

安全读取返回 `ESTALE`/`EIO` 时，可能已经读取本次允许的全部字节，因此按本次读取上限保守扣除预算；缺失、拒绝和读取前发现超限不扣读取字节预算。不能通过连续改变源文件绕过累计读取上限。

这些上限使单件内存占用、文件访问次数及工具资产磁盘用量有明确边界。清单用流式写入，不因历史引用总数增长而把所有事件或文件内容存入内存。达到预算时，清单明确说明尚未检查的 JSON 依赖；不得暗示其内部已完整枚举。

Markdown 附工具产物清单，至少标明来源事件、工具名、资源编号和状态。已打包项使用相对链接，记录实际导出字节数和 SHA-256；JSON 项注明为用户可见字段投影。重复项指向同一资源编号。未打包项分别说明缺失、路径拒绝、单件超限、总量/件数上限、内容格式无效或读取失败。不展示原生异常中的多余内部信息，不把未知失败误报为文件不存在。

预期的资源缺失、拒绝与预算限制允许导出成功，但必须留下上述提示。宿主安全读取程序不可用、协议错误、取消、输出目录写入失败等基础设施故障必须使导出失败，不能伪装为资源缺失而产出看似完整的文件。

## 发布与结构

保持原有唯一文件名、私有目录/文件权限和发布顺序：先写临时 Markdown 与本次资产目录，全部处理完成后关闭文件，再重命名发布 Markdown。发生致命错误时关闭句柄并删除临时 Markdown、本次资产目录；不能删除其他导出或源产物。此流程保证成功结果的发布边界，不声称能在进程强制终止时自动清理所有遗留临时文件。

工具清单完成后以及最终 Markdown 句柄关闭后都检查取消信号。调用发布重命名前是取消检查的提交点；最后清单写入或关闭期间收到的取消必须拒绝导出并清理临时产物，不声称能撤回已经提交的重命名。

实现使用现有 TypeScript、SQLite worker、Node 文件 API 和 secure-file-helper，无新依赖。共享授权读取逻辑放在 `packages/runtime/src/session-artifacts.ts`，存储分页在 `packages/storage/src/index.ts` 与 `worker.mjs`，导出协调在 runtime；`apps/cli/src/rpc-library.ts` 复用 helper 并保持现有 `artifact.read` 响应和权限契约。新增逻辑可拆独立导出模块，避免继续扩大 runtime 主文件。

沿用现有命名与格式，白名单投影必须显式构造，例如：

```ts
const visible = {
  text: source.text,
  ...(typeof source.isError === "boolean" ? { isError: source.isError } : {}),
};
```

## 实现顺序与验收

先写失败测试，再补引用分页和共享安全读取；随后接入导出、清单、预算及清理；最后验证两种 TUI 共用路径。root 统一安排提交、完整检查和受影响的构建产物测试，避免与执行历史收尾并发修改共享文件。

定向验证命令为 `pnpm exec vitest run tests/export-tool-artifacts.test.ts tests/rpc-library.test.ts tests/session-settings.test.ts tests/attached-navigation-pty.test.ts`，随后运行 `pnpm typecheck` 与 `pnpm build`。整合后运行 `pnpm check`；不因本切片调用真实模型、真实外部附件或额外性能基准。

必须覆盖：

- 超过一页的源事件，无引用空页仍推进，固定水位后新增事件不进入导出，跨会话不泄漏。
- JSON 投影及嵌套日志移动后可读，普通日志字节不变；内容 SHA-256 对应实际导出文件。
- 顶层和 JSON 中放入 `providerData`、嵌套私有标记及未知字段，导出不能包含它们；原文本、错误状态与既有图片仍按契约保留。
- 同一引用跨页出现只读取一次，两个已知字段都处理；重复、循环或嵌套 JSON 不造成递归读取。
- 源文件缺失、非法路径、跨会话引用、文件和父目录符号链接、非对象 JSON、缺少文本字段都有准确状态。
- 单件、件数、累计源读取及累计写入预算的边界；后续引用有明确提示，不能静默丢弃或写出截断内容。
- 致命读取/写入失败不发布 Markdown，清理本次临时资产且保留其他导出。
- 原隐藏 thinking、provider 私有字段排除、跨块图片导出保持通过。一个现有附着 TUI PTY 场景实际执行 `/export` 并验证相对工具资产链接；普通入口通过同一 runtime 定向测试覆盖。

验证记录写入 `docs/validation/export-tool-artifacts.md`。尚未覆盖的外部附件、超过上限的完整日志、真机移动端分享与强制终止清理不得记为已交付。
