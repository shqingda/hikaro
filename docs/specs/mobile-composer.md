# 移动端发送与离线草稿

目标：手机在已有授权任务中输入多行要求，空闲时发送、运行中加入待发队列；离线时保存草稿，回到前台或重建应用后恢复。补充当前模型轮的 steering 单列后续操作，不把排队 prompt 冒充 steering。

## 用户行为与边界

- 使用现有原生 @expo/ui TextInput / Button，任务页直接编辑，回车换行；发送必须显式点击。允许离线编辑，连接恢复不自动发送。
- 草稿按 relay、host ID/key、device ID 和 session ID 隔离。持久保存必要的最近任务身份/标题以便应用在离线重开时找到草稿，明确显示为离线内容，不能据此授予控制权。不扩展为本地持久聊天历史。
- 在任务列表断线后，仍可返回当前保留的任务，查看本机快照与草稿。离线、重连中或连接失败时，仅在当前任务与已加载草稿属于同一 session 时开放入口；草稿加载中、任务不匹配、后台、恢复身份中或连接已锁定时不开放。只有快照时，沿用控制器为该任务恢复的空草稿。入口注明离线状态，点击时重新检查当前状态；不选择其他任务、不恢复发送权限，也不自动提交草稿。
- 输入先更新编辑器，异步串行保存最新版本。保存失败保留屏幕原文并显示错误；不能用失败或过期读取覆盖新编辑。后台隐藏内容但保留已发起保存；撤销或移除配对时清理对应草稿，晚到操作不得重新写回。
- 发送校验当前在线、任务归属、control/owner 角色及主机能力。校验须覆盖落盘等待后的任务切换；旧页面的点击或回执不能改另一任务草稿。运行中提示加入待发队列，接受回执不是模型完成。
- 发送前将原文与稳定命令 ID 一起保存。ClientConnection 增加可选调用者提供 ID 的非破坏性参数，沿用现有意图持久化及主机去重；不增加任何重放机制。
- 发送期间保留原文。已确认接收后清空对应版本；丢回执、超时或崩溃时展示待核对，重连只查询该 ID 的持久回执。失败/未知项不自动重发；再次编辑或发送必须经过明确的恢复为草稿动作，提示先核对电脑记录，避免重复执行。清理草稿失败也不能伪报已清理。

## 实现与验证计划

新增独立 composer/draft 模块，避免继续将存储与状态分支堆进 MobileController。扩展 native-storage 的 SQLite 表，沿用 WAL/FULL 和控制器现有串行凭据/撤销边界。由 controller 接入连接、选择、回执及后台事件；任务页使用独立 Composer 组件，并更新旧的“只读模式”说明与回执标签。

先在定向测试证明：离线应用重建、按任务/身份隔离、晚到加载不覆盖输入、写入失败、发送前持久化、任务切换、正常回执清理、丢回执恢复不重发、撤销与写入竞争。`tests/mobile-controller.test.ts` 的实际 shared host + 加密传输 fixture 为本轮唯一端到端场景，验证新请求、运行中排队和丢回执/重连。必要 client-core 定向契约测试、根目录/移动端类型检查以及双平台 Hermes 导出；原生操作与真机结果另记，不以 JS fixture 替代。
