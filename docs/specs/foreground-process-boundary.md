# 前台命令的进程与输出边界

## 行为

Shell 的取消和超时只停止本次创建的原始进程组：SIGTERM 后最多等待 1 秒，仍存在则 SIGKILL，再等最多 2 秒。只有主进程退出且原组消失才报告 `cleanup: confirmed`。信号失败或超时核实失败报告 `cleanup: failed`、原因及“进程可能仍存活”；未知退出码保持 `null`。确认原组消失后不再向同一数字 PGID 发信号。

主进程 exit 与输出 close 分开处理。主进程退出或停止尝试结束后，最多等待输出管道关闭 1 秒；仍未关闭则关闭本次调用持有的流，标记 `outputIncomplete`。日志收尾也最多等待 1 秒，失败明确报告。可能持有管道的脱离进程不被当作终止目标；关闭管道可能影响后续写入，不能称作无影响地继续运行。返回后停止原调用的计时器、取消监听和探针，不向旧 PGID 自动重试。旧进程仍可能继续产生文件副作用，不宣称已隔绝后继任务。

## 观察与证据

Shell 显式启用 macOS 父子关系探针，复用后台 PTY 的 PID + 启动时间检查及 256 节点/16 层/1 秒/128 KiB 限额。`runProcess` 默认不探测，`rg`、索引与 Git 读取不额外启动原生扫描。观测只持续到调用返回，之后的后台写入不在该证据范围。

工具结果保留退出码/信号、原组清理、输出完整性、观察摘要，各自独立。重要警告放在文本开头，避免前缀截断丢失结论。core 在普通取消后仍记录已执行工具的大结果，但 artifact 与事件保存继续受当前租约保护；截断只保留不超过 8 KiB UTF-8 JSON 的普通对象 data，大对象仍使用完整结果 artifact。

完整 Shell 路径还包含最多 5 秒的修改快照收尾。因此进程管理的等待界限不等于整个工具调用的总时限。非 macOS 不提供后代探针；Windows 仅保留直接子进程终止尝试，明确无法确认整个进程组。本轮不新增跨平台支持保证。

## 实现依据

Node 的 [exit/close 事件说明](https://nodejs.org/api/child_process.html#event-close) 区分主进程退出与 stdio 关闭；多个进程可能共享输出流。此边界用于避免脱离后代继承管道导致永久等待，不代表完整 daemon 容器隔离。
