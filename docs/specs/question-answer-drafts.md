# 未提交问题答案草稿

普通和附着 TUI 的结构化问答保存已选择答案、自由输入原文和当前题目/输入/汇总位置。自由文字不必按回车才保存。恢复只预填原问题面板，显示恢复提示；用户仍须核对并明确提交。恢复不调用模型、不恢复工具等待、不改变 Plan，也不自动派发待发消息。

草稿绑定持久问题组 UUID、审批归属会话和原 scope。SQLite 新表保存 revision 与完整草稿；不存在或已结算的问题不能读取或新建草稿。每次读取、保存和带草稿版本的提交都重新检查问题身份、工作区和控制权限。仅支持原题 ID，每个答案/输入最多 100,000 个 UTF-16 单元，完整 JSON 最多 512 KiB。登录等秘密输入不触发草稿回调。

输入按 300 ms 合并，持续输入不会无限延迟保存；同一面板串行提交递增版本。SQLite 在事务内比较 expectedRevision，两个视图从同一版本保存时只有一个成功。冲突明确提示关闭并重新打开原问题，不采用新版本号覆盖另一视图内容。保存失败保留当前面板原文，停止自动重试循环；用户可在提交时手动重试。连接或会话改变后，旧面板和迟到回复失效。

提交前排空本面板的草稿写入，并将 draftRevision 交给问题结算事务再次核对。回答或显式取消、清除草稿和原有事件/上下文保存属于同一事务；失败回滚并保留草稿。会话删除清除草稿，已结算问题的迟到保存不得重新创建记录。没有活跃执行租约的要求只适用于恢复答案结算，不能阻止运行中问题保存草稿。旧客户端不发送 draftRevision 时保持既有兼容行为。

RPC 增加 capability 可发现的 `questions.draft.read` 与 `questions.draft.save`。两者可在普通请求队列等待模型期间处理；保存是独立 CAS 状态更新，不写任务动作回执、不进入客户端恢复意图队列、不自动重发，仍按非只读请求检查权限。旧 host 不提供能力时，附着面板沿用原问答功能，不承诺草稿持久恢复。

普通 TUI 正常退出在关闭问题服务前发起最后一次写入，并等待已接收写入结束。强制终止、断线或窗口失效前最后约 300 ms 及尚未完成的写入仍可能丢失；不承诺断电或进程崩溃时零丢失。仅限结构化问答，未扩展到插件输入、登录密码、普通编辑器之外的任意临时面板。

验收包含真实 SQLite 多连接竞争、权限和租约、原子清理与故障回滚、保存失败和输入隔离，以及普通/附着实际 PTY 的多题选择、中文/emoji 未回车输入、SIGKILL、恢复后不执行、显式提交后清理。结果单独记录，不将 fixture 当作真实模型或物理终端输入法验收。
