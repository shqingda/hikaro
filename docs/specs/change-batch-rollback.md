# 回退到此处（多文件批量回退）

普通与附着 TUI 的 `/changes` 详情页新增“Roll back to here…”：从最新的修改开始，依次回退选中修改及其之后、仍为 `committed` 的全部记录。它组合既有的单条 `rollback`，协议与日志格式不变，附着 TUI 通过既有 `changes.rollback` 获得同样能力。

## 范围与顺序

- 目标为列表中（按时间从新到旧）从最新一条到选中条目之间、状态为 `committed` 的记录；已 `reverted` 的跳过。
- 范围内若有 `prepared` 或 `reverting`（上次写入或回退未完成），整批拒绝，不回退任何文件。
- 选中条目自身必须是 `committed`；只有它一条时不提供批量入口，沿用单条回退。
- 从最新到最旧逐条执行。同一文件的多次修改由此按相反顺序恢复，每一步都满足单条回退“当前内容等于该次修改结果”的冲突检查。

## 确认与失败

- 确认页列出条数、涉及的文件及“新建文件将被删除”的数量，默认焦点为取消，须完整显示说明后才能确认。
- 任一条失败（冲突、状态变化、取消）立即停止：已回退的保持回退，未执行的保持原状，不自动重做。结果明确显示“已回退 N/M”、停止处的文件和原因。
- 不是事务：没有跨文件原子性；文件在执行期间被外部修改时，由单条冲突检查拒绝并停止。

## 验收

单元测试覆盖目标选择、跳过与拒绝。真实 `ChangeJournal` 与临时文件覆盖：两个文件三次修改的整批恢复；中途冲突时停止、报告进度且保留较新内容。面板流程测试覆盖入口、确认及结果提示。定向测试、类型检查后运行 `pnpm check`。

不覆盖：按模型轮次聚合、Shell/插件/子 agent 修改、跨文件原子性。
