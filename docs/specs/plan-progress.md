# 计划逐步骤进度

普通与附着 TUI 在批准计划后，可通过 `/plan progress` 只读查看该计划每一步的执行状态。状态由模型在执行中通过 `update_plan_step` 报告，界面明确标为“模型报告”，不等同于已验证完成；实际结果仍以 `/changes`、测试和执行历史为准。

## 状态与持久化

- 批准计划时，为该计划 ID 初始化与步骤数相同的进度，全部为 `pending`。
- `update_plan_step` 参数：`plan_id`（UUID）、`step`（从 1 开始）、`status`（`pending`、`in_progress`、`completed`、`blocked`、`skipped`）、可选 `note`（≤500 字符）。
- 仅当 Plan 模式未激活、当前计划即已批准计划、`plan_id` 与进度所属计划一致且步骤在范围内时写入；否则返回工具错误，不修改状态。Plan 只读模式下该工具不在允许集合内。
- 进度与计划状态同文件、同原子写入；重新进入 Plan 模式或提交新计划时清除旧进度。历史计划版本不保存进度。
- 重启后进度保留，不自动恢复或续跑执行。

## 入口

- 普通 TUI：`/plan progress` 打开只读文档，显示计划标题、每步状态与备注；没有已批准计划时提示原因，不进入 Plan 模式。
- 附着 TUI：`plan.read` 在新 host 上附带 `progress`（无进度时为 `null`）；旧 host 不含该字段时提示升级，不猜测状态。
- 执行提示要求模型在开始与完成每一步时调用 `update_plan_step`。

## 验收

单元测试覆盖初始化、更新、身份/范围/模式拒绝、清除与持久化重读。普通 TUI 真实 PTY（本地模型 fixture）在执行中报告步骤后，用 `/plan progress` 看到对应状态。附着入口用定向测试覆盖新旧 host 行为。定向测试、类型检查、构建后运行 `pnpm check`。

不覆盖：真实模型是否可靠调用该工具、自动核对模型报告与实际修改的一致性、移动端显示。
