## TUI v0.1 的发布门槛

1. 在真实项目、真实模型上完成读取→修改→验证→审阅闭环；拒绝、取消、断网、限流、host 重启后状态可核对，不重复执行。新恢复分支完成合并审查和针对发布版本的回归验证。
2. 时间性能标准保持。已验证构建的启动 p95 为独立 174.58 ms、附着 188.54 ms，均通过 200 ms 原门槛。共享 host + TUI 合计 RSS 可能重复计算共享映射，原 100 MiB 不再用于否决 release。按[修订口径](specs/shared-memory-soak.md)完成了 [30 分钟基线与稳定性记录](validation/shared-memory-soak.md)，后续队列收尾竞态也已修复；这些历史样本不冒充当前包重新测得的性能结果。
3. 在实际终端检查中文 IME、粘贴、快捷键、窄窗、完整工具输出阅读及退出恢复，修复阻塞日常使用的问题。
4. 完成干净环境安装/升级、发布包、版本与 changelog、数据兼容及回退说明；安排连续真实使用窗口后再切正式版本。

建议先完成最小必要的历史执行核对及取消终态缺口，然后冻结增强功能。批量回退/redo、嵌套任务树、高级搜索、完整 Pi 互通和资源市场不应全部成为 v0.1 的前置条件；对外明确支持范围。steering 持久保存和原身份确认恢复已纳入 cf57c46 验证候选。之后的新产品改动仍须进入新候选验收；不可把旧包证据用于新代码。
