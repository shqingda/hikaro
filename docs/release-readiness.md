## TUI v0.1 的发布门槛

1. 在真实项目、真实模型上完成读取→修改→验证→审阅闭环；拒绝、取消、断网、限流、host 重启后状态可核对，不重复执行。新恢复分支完成合并审查和针对发布版本的回归验证。
2. 原性能标准不降低。最后保存的启动 p95 为独立 230.86 ms、附着 203.82 ms，仍高于 200 ms；这是历史最新记录，并非本轮新增恢复后的复测。共享总 RSS 124.78 MiB 必须按真实合计口径核验，不能拿界面单进程替代。另补长历史、大输出和 30 分钟稳定性验收。
3. 在实际终端检查中文 IME、粘贴、快捷键、窄窗、完整工具输出阅读及退出恢复，修复阻塞日常使用的问题。
4. 完成干净环境安装/升级、发布包、版本与 changelog、数据兼容及回退说明；安排连续真实使用窗口后再切正式版本。

建议先完成最小必要的历史执行核对及取消终态缺口，然后冻结增强功能。批量回退/redo、嵌套任务树、高级搜索、完整 Pi 互通和资源市场不应全部成为 v0.1 的前置条件；对外明确支持范围。steering 当前内存语义需显式说明，不能宣传所有队列都可跨重启恢复。

## 移动端 v0.1 的发布门槛

1. M0 真机验收：iOS/Android 原生运行、真实相机扫码、安全存储、设备撤销、网络切换、断网、锁屏、进程终止与前台恢复。
2. M1 闭环：完整工具审批详情、补充指令、停止、离线未发送草稿和操作回执；真实电脑任务能从手机接续。过期审批不可使用、结果未知的操作不自动重发。
3. 发布构建验证：启动/输入/流式指标、30 分钟内存与耗电、大字体及辅助技术、签名与分发。真实 relay 网络和双端竞争必须有证据，不能用模拟器或加密 fixture 代替。

图片/diff 增强和通知可按 v0.1 明确范围拆到后续；审批、补充、停止属于当前已确认的成品定位，不应省略后仍称为完整控制器。
