# Client core — C0 contract

This package contains a portable execution-state reducer and an optional raw-transport controller, not a GUI or a new execution owner. Its import closure uses portable Zod wire contracts with no Node/DOM ambient types. Platforms inject the transport, unique IDs and a cancellable clock. Native transports and credentials remain outside this package.

## Contract before implementation

1. `hello` is an additive protocol-v2 control method. An optional bounded `protocolVersions` list must include v2. Its response enumerates actual RPC methods, `session.current` as the snapshot method, globally monotonic event sequence filtered by session, and explicit limits. Existing ready frames/methods retain their meaning. Host incarnation and durable receipt capabilities are negotiated; new hosts also supply run IDs and status in snapshots. The legacy `runIdentity` marker stays unchanged for old-v2 compatibility; `runSnapshotIdentity: true` advertises the addition.
2. `ClientState.beginConnection()` advances a connection epoch. Unanswered commands become `unknown`; a disconnected client cannot send. `command(id, method, params)` only prepares a frame. The caller writes it once; this package never sends, retries, reconnects, or replays an operation.
3. Feed **all complete raw RPC frames in wire order** to `receive(epoch, frame)`. A correlated `hello` response enables `session.current`; its correlated response establishes snapshot state synchronously. Do not feed promise results after later events: use the raw observer on ProcessClient or an equivalent transport parser. While awaiting a snapshot, buffer at most 128 notifications/1 MiB. The host adds a per-scope revision to notifications and snapshots: discard buffered revisions covered by the snapshot, then apply strictly contiguous newer revisions. This also handles a remote wrapper delivering later notifications before its snapshot response. Buffer overflow requires another snapshot.
4. Scope/session mismatches and duplicate/old sequence numbers never change the selected state. A notification revision gap disables new mutations until a fresh snapshot. New frames after the barrier update stream, run state and approvals. A snapshot restores its explicit run ID/status; an old snapshot without those fields retains the conservative unknown/idle behavior. `busy` alone does not imply a known operation identity.
5. Pending approvals belong to the scope and session captured by the host. Resolution removes by ID. Disconnect or a gap makes `canAct` false; cached state may be displayed but never treated as an actionable approval.
6. SQLite event sequence numbers may skip values consumed by other sessions; only scope notification revision gaps require a snapshot. Keep only the last 64 event summaries, a 100,000-character stream, at most 64 approvals, and 64 command receipts. Reserve four slots for recovery reads; at most 60 pending, acknowledged or unknown mutations remain unresolved. Evict only completed/failed receipts or settled/unknown reads, and reject excess mutations rather than discard uncertainty. Command IDs must remain unique across the caller's lifetime; an evicted settled receipt is not durable deduplication.
7. Transport loss or timeout means unknown, not failed or safe to resend. A snapshot does not resolve unknown commands. `command.receipt` can explicitly reconcile unknown/acknowledged outcomes after handshake, even before a fresh snapshot. A missing receipt leaves uncertainty intact. Host receipt status never automatically changes the selected run or resends a mutation. Attachment management remains a later slice.
8. Validate incoming recognized frames and reject oversized/malformed state. Never store arbitrary RPC results or unbounded history in this reducer. `messages.read`/artifact browsing remains a separate paginated layer.

## Connecting an existing local transport

`ProcessClient.observe` receives raw responses and notifications in wire order even when no `request()` promise owns the ID. Use `send(state.command(...))` once and feed the observer to `state.receive(epoch, frame)`. On transport failure call `state.disconnected(epoch)`; on a new transport call `beginConnection()` and explicitly send `hello`, then `session.current`. Catch validation errors in the observer to show an error state. Calling `request()` and `send()` for the same prepared command would send twice: use one path.

A remote adapter must expose the same raw frame stream and bind `ClientState.scope` to the authenticated device ID; do not replace the server-selected scope with a handset-provided value. `RemoteClient.observe/send` and `packages/remote/src/connection.ts` now provide that path, retaining the existing authenticated channel and reconnect policy. This is tested with a real CLI/SQLite host and an encrypted in-process socket fixture, not a production relay or native mobile runtime.

## Raw connection controller

`ClientConnection` in `src/connection.ts` handshakes and restores a snapshot when the platform reports a connection. It sends every prepared frame once, bounds pending requests to 32 with recovery slots, applies a 30-second timeout by default, and marks interrupted outcomes unknown. Revision gaps and session invalidation trigger safe snapshot reads. It queries durable receipts after mutation replies; `reconcile()` explicitly checks remaining acknowledged/unknown outcomes. It never resubmits mutations. The platform must fence callbacks from obsolete transports and call `disconnected()` on transport loss.

The controller's intent ledger is currently in memory. Native clients still need durable intent metadata before sending, isolated by host/workspace/device, so app termination does not lose unknown command IDs. This limitation is separate from the host's already durable receipts.

## Client library APIs

Capabilities now enumerate `workspace.current`, session rename/delete/export and title/ID search, draft read/save, model list/read/set/default, message content and restricted artifact reads. Credential management stays on the host; remote model selection cannot supply an endpoint. Session projections omit the stored endpoint. Active and saved default selection remain separate.

`messages.read` returns stable sequence pages bounded to roughly 450 kB, with text previews (20,000 UTF-16 units), thinking previews (4,000), image counts and explicitly truncated tool-call metadata. `messages.content` reads text/thinking/toolCalls JSON or base64 image segments by session + event sequence; offsets are UTF-16 units (ASCII characters for base64), at most 65,536 per response. It never exposes provider-native payloads. `events.read` returns a bounded prefix of a sequence page and reports an unpageable first event explicitly instead of silently dropping it or closing the channel.

`session.export` reads Markdown segments against a stable `through` sequence watermark. Carry `through/after/nextOffset` into the next request; no host path is returned. `artifact.read` accepts only the sequence of a host-authored `tool.end` reference inside that session's artifact/output directory, passes the native no-symlink helper, and returns base64 byte ranges (up to 49,152 bytes) with a SHA-256 digest. Pass the digest on later reads to detect changes. Files above the explicit 16 MiB secure snapshot limit fail visibly; 50 MiB process logs do not gain a new unsafe fallback. These APIs are not arbitrary path or URL readers, nor a portable attachment export format.

`tests/client-transports.test.ts` covers local/encrypted-remote convergence, duplicate/gap notifications, dropped prompt replies, reconnect, receipt reconciliation and more than 60 settled draft writes. `tests/rpc-library.test.ts` covers large multilingual messages, image segments, complete paged text export, provider-data exclusion, artifact ranges/change detection and symlink denial. Only affected tests are required for changes to these paths.

## Implemented verification

The handshake test first failed because the old protocol rejected `hello`; portable tests first failed because the package did not exist. Targeted tests now cover the real RPC handler, real SQLite event sequence consumed by two independent scopes, offline demo completion/reconnect, raw ProcessClient response ordering, malformed image rejection before run.start, and the reducer's bounded state/recovery rules. Existing RPC control tests remain compatible. Exact run counts are reported in the work summary; no full suite or performance benchmark is implied.

`pnpm exec tsc -p packages/client-core/tsconfig.json` checks the import closure with `lib: ["ES2023"]` and `types: []`. New snapshots restore explicit `runId/runStatus`; reopened unmatched starts are unknown, not live. Host incarnation mismatch requires reconnect. Read the [durable command receipt contract](../../docs/specs/command-receipts.md) for status, scope, legacy and retention boundaries.
